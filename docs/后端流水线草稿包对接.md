# 后端流水线草稿包对接

本文面向后端流水线和后端 Codex。目标是让后端复用已有 ffmpeg 产物，最小成本生成可导入剪映的草稿包。

## 1. 最小包目录

后端生成一个目录，目录内必须包含 `bundle.json` 和 `assets/`。

```text
batch_demo_001/
  bundle.json
  assets/
    concat.txt
    video_001.mp4
    video_002.mp4
    subtitle.srt
    narration/
      001.mp3
      002.mp3
```

所有被引用的文件都必须放在 `assets/` 下。`bundle.json` 和 `concat.txt` 里只写相对 `assets/` 的路径，不写本机绝对路径。

## 2. bundle.json

最小可用示例：

```json
{
  "bundle_version": 1,
  "bundle_type": "pipeline_package",
  "project_id": "batch_demo_001",
  "project_name": "批量草稿_001",
  "assets_dir": "assets",
  "pipeline": {
    "concat_file": "concat.txt",
    "subtitle_file": "subtitle.srt",
    "narration_files": [
      "narration/001.mp3",
      "narration/002.mp3"
    ]
  },
  "subtitle_style": {
    "font_size": 8.0,
    "x": 0.5,
    "y": 0.82
  },
  "audio_style": {
    "video_volume": 1.0,
    "narration_volume": 1.0
  }
}
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `bundle_version` | 是 | 固定为 `1` |
| `bundle_type` | 是 | 固定为 `pipeline_package` |
| `project_id` | 否 | 后端业务 ID，建议填写 |
| `project_name` | 否 | 导入后的草稿名称 |
| `assets_dir` | 否 | 素材目录，默认 `assets` |
| `pipeline.concat_file` | 是 | ffmpeg concat 文件 |
| `pipeline.subtitle_file` | 是 | SRT 字幕文件 |
| `pipeline.narration_files` | 是 | 分段解说音频列表，顺序必须对应 SRT |
| `subtitle_style.font_size` | 否 | 字幕字号，默认 `8.0` |
| `subtitle_style.x` | 否 | 字幕横向位置，`0.5` 是居中 |
| `subtitle_style.y` | 否 | 字幕纵向位置，越大越靠下，默认 `0.82` |
| `audio_style.video_volume` | 否 | 视频原声音量，默认 `1.0` |
| `audio_style.narration_volume` | 否 | 解说音频音量，默认 `1.0` |

## 3. concat.txt

只支持 ffmpeg concat demuxer 的 `file` 子集。

```text
file 'video_001.mp4'
file 'video_002.mp4'
```

限制：

- 每个有效行必须是 `file '相对路径'`
- 路径相对 `assets/`
- 不支持 `duration`、`inpoint`、`outpoint` 等其他 concat 指令
- 不支持绝对路径
- 不支持 `..`
- 不支持 Windows 反斜杠 `\`
- 不支持 URL

导入后会生成一条 `main_video` 视频轨，按 `concat.txt` 顺序整段拼接。

## 4. subtitle.srt

使用标准 SRT。

```srt
1
00:00:00,000 --> 00:00:02,400
第一句字幕

2
00:00:02,400 --> 00:00:05,100
第二句字幕
```

导入后会生成一条 `subtitle` 字幕轨，字幕在剪映里可编辑。

要求：

- 每条字幕必须有开始和结束时间
- 结束时间必须大于开始时间
- 字幕结束时间不能超过拼接后视频总时长
- 多行字幕会保留换行

## 5. 解说音频规则

`pipeline.narration_files` 会生成一条 `audio` 音频轨，轨道内包含多个解说片段。

规则：

- 视频原声默认保留
- SRT 是唯一时间源
- `narration_files.length` 必须等于 SRT 字幕条数
- 第 N 个解说音频对应第 N 条 SRT 字幕
- 解说音频片段从对应 SRT 的开始时间开始
- 解说音频长于对应字幕时，自动裁到字幕结束
- 解说音频短于对应字幕时，不自动循环或补齐

示例：

```text
subtitle.srt 第 1 条：00:00:00,000 --> 00:00:02,400
narration_files[0]：narration/001.mp3
导入结果：001.mp3 放到 0 秒开始，最多播放 2.4 秒
```

## 6. 后端生成步骤

伪代码：

```text
create directory package_root
create directory package_root/assets

copy all concat videos into package_root/assets
write package_root/assets/concat.txt
copy or write narration audio files to package_root/assets/narration/
write package_root/assets/subtitle.srt
write pipeline.narration_files in the same order as subtitle.srt cues
write package_root/bundle.json

call jy_cli import-bundle with source=package_root and output=draft_output_dir
```

路径示例：

```text
D:\pipeline\batch_demo_001\
D:\pipeline\batch_demo_001\assets\
D:\JianyingPro Drafts\batch_demo_001\
```

## 7. Windows 导入命令

PowerShell：

```powershell
cargo run -p jy_cli -- import-bundle `
  --source "D:\pipeline\batch_demo_001" `
  --output "D:\JianyingPro Drafts\batch_demo_001"
```

如果后端调用编译后的可执行文件：

```powershell
target\release\jy_cli.exe import-bundle `
  --source "D:\pipeline\batch_demo_001" `
  --output "D:\JianyingPro Drafts\batch_demo_001" `
  --output-format json
```

`--output` 目录必须不存在或为空。

## 8. 常见错误

| 错误表现 | 排查点 |
| --- | --- |
| `pipeline_package requires bundle.pipeline` | `bundle.json` 缺少 `pipeline` 字段 |
| `concat file must contain at least one file entry` | `concat.txt` 没有 `file '...'` 行 |
| `only supports file entries` | `concat.txt` 包含 `duration`、`inpoint` 等不支持行 |
| `must be relative` | 路径写成了 `D:/...` 或其他绝对路径 |
| `path separator` | 路径里用了 Windows 反斜杠 |
| `not found` | `bundle.json` 或 `concat.txt` 引用的文件不存在 |
| `pipeline.audio_file is no longer supported` | 还在使用旧的单音频字段，改用 `pipeline.narration_files` |
| `audio_style.audio_volume is no longer supported` | 还在使用旧音量字段，改用 `audio_style.narration_volume` |
| `narration_files must contain at least one` | 没有传分段解说音频列表 |
| `must match subtitle cue count` | 解说音频数量和 SRT 字幕条数不一致 |
| `failed to load pipeline narration` | 某个解说文件不是音频，或 ffprobe 不能识别 |
| `end exceeds stitched video duration` | SRT 字幕时间超过拼接后视频总时长 |

## 9. 后端验收标准

后端生成包后，至少验证：

- `bundle.json` 存在且 `bundle_type` 为 `pipeline_package`
- `assets/concat.txt` 存在且至少包含一个 `file '...'`
- `concat.txt` 中每个视频文件都存在
- `pipeline.subtitle_file` 指向的 SRT 文件存在
- `pipeline.narration_files` 数量等于 SRT 字幕条数
- `pipeline.narration_files` 中每个音频文件都存在
- 导入后草稿目录包含 `draft_content.json`
- 草稿中存在 `main_video`、`audio`、`subtitle` 三条轨道
- `audio` 轨中的音频片段数量等于 SRT 字幕条数
- 字幕时间不超过拼接后视频总时长
