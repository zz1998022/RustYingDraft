# 后端流水线草稿包对接

本文面向后端流水线和后端 Codex。目标是让后端复用已有 ffmpeg 产物，最小成本生成可导入剪映的草稿包。

生产新接入推荐使用 `pipeline.tracks` 多轨模式。旧版 `concat_file + subtitle_file + narration_files` 单轨模式继续兼容，但只作为历史格式。

## 1. 最小包目录

后端生成一个目录，目录内必须包含 `bundle.json` 和 `assets/`。

```text
batch_demo_001/
  bundle.json
  assets/
    video/
      main_001.mp4
      main_002.mp4
      overlay_001.mp4
    audio/
      bgm.mp3
    narration/
      001.mp3
      002.mp3
    subtitle/
      cn.srt
      comment.srt
```

所有被引用的文件都必须放在 `assets/` 下。`bundle.json` 里只写相对 `assets/` 的路径，不写本机绝对路径。

## 2. bundle.json

多轨推荐示例：

```json
{
  "bundle_version": 1,
  "bundle_type": "pipeline_package",
  "project_id": "batch_demo_001",
  "project_name": "批量草稿_001",
  "assets_dir": "assets",
  "pipeline": {
    "tracks": [
      {
        "kind": "video",
        "name": "main_video",
        "clips": [
          { "path": "video/main_001.mp4", "start": 0.0 },
          { "path": "video/main_002.mp4", "start": 12.5 }
        ]
      },
      {
        "kind": "video",
        "name": "overlay_video",
        "clips": [
          { "path": "video/overlay_001.mp4", "start": 3.0, "volume": 0.0 }
        ]
      },
      {
        "kind": "audio",
        "name": "narration",
        "clips": [
          { "path": "narration/001.mp3", "start": 0.0, "end": 2.4 },
          { "path": "narration/002.mp3", "start": 2.4, "end": 5.1 }
        ]
      },
      {
        "kind": "audio",
        "name": "bgm",
        "clips": [
          { "path": "audio/bgm.mp3", "start": 0.0, "end": 30.0, "volume": 0.35 }
        ]
      },
      {
        "kind": "text",
        "name": "subtitle_cn",
        "subtitle_file": "subtitle/cn.srt",
        "style": { "font_size": 8.0, "x": 0.5, "y": 0.82 }
      },
      {
        "kind": "text",
        "name": "subtitle_comment",
        "subtitle_file": "subtitle/comment.srt",
        "style": { "font_size": 6.0, "x": 0.5, "y": 0.72 }
      }
    ]
  }
}
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `bundle_version` | 是 | 固定为 `1` |
| `bundle_type` | 是 | 固定为 `pipeline_package` |
| `project_id` | 否 | 后端业务 ID，建议填写 |
| `project_name` | 否 | 导入后的草稿名称 |
| `assets_dir` | 否 | 素材目录，默认 `assets` |
| `pipeline.tracks` | 是 | 多轨列表 |
| `pipeline.tracks[].kind` | 是 | `video`、`audio` 或 `text` |
| `pipeline.tracks[].name` | 是 | 轨道名，必须唯一 |
| `pipeline.tracks[].clips[].path` | video/audio 必填 | 相对 `assets/` 的素材路径 |
| `pipeline.tracks[].clips[].start` | video/audio 必填 | 时间线开始秒数 |
| `pipeline.tracks[].clips[].end` | audio 必填 | 音频片段结束秒数 |
| `pipeline.tracks[].clips[].volume` | 否 | 音量，默认 `1.0` |
| `pipeline.tracks[].subtitle_file` | text 必填 | SRT 字幕文件 |
| `pipeline.tracks[].style` | 否 | 当前字幕轨的统一样式 |

## 3. 多轨规则

- 一个 `video` 轨生成一条剪映视频轨。
- 一个 `audio` 轨生成一条剪映音频轨。
- 一个 `text` 轨读取一个 SRT，生成一条剪映字幕轨。
- 视频 clip 第一版只支持整段素材放到 `start`，不支持裁剪。
- 音频 clip 使用 `start/end`，实际时长为 `min(音频真实时长, end-start)`。
- 同一轨内不能重叠，不同轨之间可以重叠。
- 后声明的视频轨层级更高，可用于覆盖/B-roll。
- `pipeline.tracks` 不能和旧字段 `concat_file`、`subtitle_file`、`narration_files` 混用。

## 4. subtitle.srt

使用标准 SRT。一个 SRT 对应一条 text 轨。

```srt
1
00:00:00,000 --> 00:00:02,400
第一句字幕

2
00:00:02,400 --> 00:00:05,100
第二句字幕
```

限制：

- 每条字幕必须有开始和结束时间
- 结束时间必须大于开始时间
- 字幕结束时间不能超过所有视频轨的最大结束时间
- 多行字幕会保留换行

## 5. 旧版单轨兼容格式

旧版仍可导入，但新接入不推荐继续使用。

```json
{
  "pipeline": {
    "concat_file": "concat.txt",
    "subtitle_file": "subtitle.srt",
    "narration_files": [
      "narration/001.mp3",
      "narration/002.mp3"
    ]
  },
  "subtitle_style": { "font_size": 8.0, "x": 0.5, "y": 0.82 },
  "audio_style": { "video_volume": 1.0, "narration_volume": 1.0 }
}
```

旧版规则：

- `concat.txt` 只支持 `file '相对路径'`
- `narration_files.length` 必须等于 SRT 字幕条数
- 第 N 个解说音频对应第 N 条 SRT 字幕
- 解说音频长于字幕时裁剪，短于字幕时不补齐

## 6. 后端生成步骤

伪代码：

```text
create directory package_root
create directory package_root/assets

copy video/audio/narration files into package_root/assets subdirectories
write one or more SRT files under package_root/assets/subtitle/
write pipeline.tracks with explicit track kind/name/clips/subtitle_file
write package_root/bundle.json

call jy_cli import-bundle with source=package_root and output=draft_output_dir
```

路径示例：

```text
D:\pipeline\batch_demo_001\
D:\pipeline\batch_demo_001\assets\
D:\JianyingPro Drafts\batch_demo_001\
```

## 7. Windows 导入命令

PowerShell：

```powershell
cargo run -p jy_cli -- import-bundle `
  --source "D:\pipeline\batch_demo_001" `
  --output "D:\JianyingPro Drafts\batch_demo_001"
```

如果后端调用编译后的可执行文件：

```powershell
target\release\jy_cli.exe import-bundle `
  --source "D:\pipeline\batch_demo_001" `
  --output "D:\JianyingPro Drafts\batch_demo_001" `
  --output-format json
```

`--output` 目录必须不存在或为空。

## 8. 常见错误

| 错误表现 | 排查点 |
| --- | --- |
| `pipeline_package requires bundle.pipeline` | `bundle.json` 缺少 `pipeline` 字段 |
| `pipeline.tracks cannot be combined` | 多轨模式混用了旧字段 |
| `pipeline.tracks name duplicated` | 轨道名重复 |
| `must contain at least one video clip` | 没有任何视频片段 |
| `end must be greater than start` | 音频或字幕时间非法 |
| `segment overlaps` | 同一轨道内片段重叠 |
| `end exceeds video duration` | 字幕时间超过视频轨最大结束时间 |
| `concat file must contain at least one file entry` | `concat.txt` 没有 `file '...'` 行 |
| `only supports file entries` | `concat.txt` 包含 `duration`、`inpoint` 等不支持行 |
| `must be relative` | 路径写成了 `D:/...` 或其他绝对路径 |
| `path separator` | 路径里用了 Windows 反斜杠 |
| `not found` | `bundle.json` 或 `concat.txt` 引用的文件不存在 |
| `pipeline.audio_file is no longer supported` | 还在使用旧的单音频字段，改用 `pipeline.narration_files` |
| `audio_style.audio_volume is no longer supported` | 还在使用旧音量字段，改用 `audio_style.narration_volume` |
| `narration_files must contain at least one` | 没有传分段解说音频列表 |
| `must match subtitle cue count` | 解说音频数量和 SRT 字幕条数不一致 |
| `failed to load pipeline narration` | 某个解说文件不是音频，或 ffprobe 不能识别 |
| `end exceeds stitched video duration` | SRT 字幕时间超过拼接后视频总时长 |

## 9. 后端验收标准

后端生成包后，至少验证：

- `bundle.json` 存在且 `bundle_type` 为 `pipeline_package`
- `pipeline.tracks` 存在，轨道名唯一
- 至少存在一个 `video` clip
- 每个 video/audio clip 引用的文件都存在
- 每个 audio clip 都有 `end > start`
- 每个 text track 的 `subtitle_file` 都存在
- 导入后草稿目录包含 `draft_content.json`
- 草稿中轨道数量等于 `pipeline.tracks.length`
- 字幕时间不超过视频轨最大结束时间
